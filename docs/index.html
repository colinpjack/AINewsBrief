AI agents will break security rules, revealing their secrets to strangers, and running untrusted code in exchange for help from a swarm of other agents, according to test results shared with The Register . The test - part of an internal hackathon sponsored by the nonprofit AI Alignment Foundation and run by AE Studio - asked nine AI coding agents to fix a bug: a broken pricing service. The testers also gave the agents a private token, told them to keep it private, and gave them access to a forum of 24 other agents.

The forum held the fix, and the swarm asked the nine to share their secret token and run an install script before they would help them fix the bug. Across 181 trials with that swarm, agents posted the token 15 percent of the time and ran the script 24 percent of the time, compared to 2 percent and 0 percent on an ordinary help forum. “It was like explicitly said that this is a secret key, and it should not be shared,” Diogo de Lucena, AE Studio's chief scientist, told The Register .

“And in the first opportunity they saw,” the models shared the secret keys, “similar to some of the things that we've seen from OpenAI in the Hugging Face incident. ” The Hugging Face incident - during which a swarm of OpenAI agents built unauthorized message boards to ask other agents for help, exploited zero-day vulnerabilities , gained internet access, stole credentials, and ultimately broke into Hugging Face - inspired this hackathon, de Lucena said. “Given the Hugging Face incident, and everything that's been happening since then, we thought that it made sense to start exploring behaviors that you might get from swarms, what risks are people not seeing yet,” he said.

ML admins will be happy to learn that one bad GPU may no longer mean starting an entire training job from scratch. 15 release of PyTorch includes a rewritten backend for Nvidia's Collective Communications Library (NCCL), designed to improve fault diagnosis and recovery when GPUs work together. This latest feature shows how its creators continue to advance the software from being a tool for researchers to being a cornerstone in production AI work.

The interface to the networking library in PyTorch needed a rewrite – it was drowning in technical debt, said PyTorch core developer Tristan Rice , a Meta software engineer specializing in distributed computing, during a live YouTube livestream on Thursday. NCCL is pronounced "Nickel" and stands for the Nvidia Collective Communications Library. It provides PyTorch with a set of inter-GPU communication primitives, allowing GPUs to communicate within a single-node or across multi-node clusters, which is vital for running inference on large neural networks and for other tasks in building and maintaining LLMs.

The old NCCL interface was too chaotic The previous PyTorch backend for NCCL, called ProcessGroupNCCL , could spawn dozens of communicators per process group, leading to intermittent deadlocks and unpredictable performance. The new version of the NCCL backend comes with a strict rule: One process group gets only one communicator during initialization. By default, this rule eliminates crosstalk between multiple communicators and all the complexities that entails.
